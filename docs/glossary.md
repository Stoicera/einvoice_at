# Glossary / Glossar

German domain terms stay German in code, docs and messages where they are legally precise. English explanation for each.

| Begriff (DE) | English explanation |
|---|---|
| **ebInterface** | Austrian national XML e-invoice standard, maintained by AUSTRIAPRO. Version 6.1 is current; 7.0 announced for Q4 2026. |
| **Auftragsreferenz** | Order reference. Mandatory for invoices to the Austrian federal government (B2G via e-rechnung.gv.at). |
| **Lieferantennummer** | Supplier number assigned by the contracting authority; required in federal B2G invoices. Canonical `Invoice.supplierNumber`, mapped to `Biller/InvoiceRecipientsBillerID` in ebInterface 6.1 (module `mapping`), enforced on the validation side by `AT-B2G-04` (`validation/src/main/resources/schematron/at-b2g-ebinterface-6.1.sch`, M3). |
| **USt** | Umsatzsteuer — Austrian VAT. Standard rates: 20 %, reduced 13 % / 10 %, plus 0 % and reverse charge. |
| **UID(-Nummer)** | Umsatzsteuer-Identifikationsnummer — VAT identification number (ATU…). |
| **e-rechnung.gv.at** | The Austrian federal portal/web service that receives B2G e-invoices (ebInterface or Peppol BIS). |
| **Prüfbericht** | Validation report. The structured, German-first output of the validation pipeline. |
| **kaufmännisches Runden** | Commercial rounding: round half away from zero (`HALF_UP`). The rounding mode used throughout `Money`. |
| **Kennzahl (KZ)** | Figure/total field referenced in Austrian tax contexts, abbreviated KZ (see SPEC §7: KZ totals); used in total-consistency business rules. |
| **Kleinunternehmer** | Small-business owner exempt from USt per § 6 Abs 1 Z 27 UStG. Modelled as VAT category E (exempt) without a UID. |
| **Schematron** | XML rule-validation language: business rules expressed as XPath `assert`/`report` statements, layered on top of a schema for checks XSD alone cannot express (e.g. "if category X then field Y is required"). ebInterface ships no official Schematron, so the `validation` module's `AT-B2G-01`/`03`/`04`/`05` rules run a project-own `.sch` file (see ADR-0004); Peppol BIS 3.0's official Schematron rule sets (via phive-rules) arrive with M4. |
| **SVRL** | Schematron Validation Report Language — the XML output a Schematron engine produces, one `successful-report`/`failed-assert` element per rule per node checked. `SchematronStage` maps each `failed-assert` to a bilingual `Finding` via `SchematronRuleCatalog`. |
| **Storno** | Cancellation/reversal of an invoice. Some senders express a Storno as a standard type-380 commercial invoice with a negative payable amount instead of a proper type-381 credit note; the canonical model's non-negative `payableAmount` invariant rejects that shape as constructed, so import mapping (M4) must normalize a negative-total 380 to a 381 before it reaches `core` (ADR-0003). |
| **Prüfsumme** | Checksum. Used here for the IBAN mod-97 checksum (`AT-B2G-02`, module `validation`): the check digits sit at positions 3–4, immediately after the two-letter country code, and a valid IBAN yields mod-97 remainder of 1 when the first four characters are moved to the end before computation. This catches a transposed or mistyped digit that a plain length/shape check (the XSD) would miss. |
| **Bundesdienststellen** | Austrian federal government service units / agencies. The AT-B2G Schematron rules `AT-B2G-01`/`03`/`04`/`05` (`validation/src/main/resources/schematron/at-b2g-ebinterface-6.1.sch`, `SchematronRuleCatalog.java`) require an Auftragsreferenz, a Biller e-mail address, a Lieferantennummer and a `PaymentMethod` respectively for invoices addressed to Bundesdienststellen, per e-rechnung.gv.at's federal B2G obligation. |
| **Empfängerkonto** | Beneficiary/recipient bank account. The IBAN mod-97 checksum rule (`AT-B2G-02`, `BusinessRuleStage.java`) validates every IBAN present under `PaymentMethod/UniversalBankTransaction/BeneficiaryAccount` (Empfängerkonto) without ever echoing the IBAN itself in the finding — only its 1-based position among the document's beneficiary accounts. |
| **Übergang der Steuerschuld** | Transfer of VAT liability to the invoice recipient — the legal effect of reverse charge (§ 19 UStG). § 11 Abs 1a UStG requires the invoice to carry a Hinweis auf den Übergang der Steuerschuld; `InvoiceToEbInterface61Mapper.exemptionComment` leads a category-AE tax item's comment with this exact wording, distinct from the `"Steuerbefreiung: "` lead-in used for a genuine tax exemption (category E) — reverse charge is a liability shift, not an exemption, and labeling it one is the kind of wording an Austrian auditor flags (M2 hostile-review finding A4; see the mapper's own Javadoc mapping table for the two wordings side by side). |
| **Rechnungssteller** | Invoice issuer (the ebInterface `Biller`). e-rechnung.gv.at's federal B2G profile requires a Rechnungssteller contact e-mail address (`Biller/Address/Email`); the AT-B2G Schematron rule `AT-B2G-03` (`validation/src/main/resources/schematron/at-b2g-ebinterface-6.1.sch`, M3) enforces its presence. |
| **Zahlungsmethode** | Payment method (the ebInterface `PaymentMethod` element). The AT-B2G Schematron rule `AT-B2G-05` (M3) requires one to be present — either `UniversalBankTransaction` or `NoPayment`, the only two variants `InvoiceToEbInterface61Mapper` ever emits. |
